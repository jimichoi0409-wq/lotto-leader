## 매주 당첨번호 업데이트 방법

1. `2_data/lotto.csv` 맨 위(헤더 아래)에 한 줄을 추가합니다. 예: `1238,,1,2,3,4,5,6,7`
   - 추첨일은 비워 두면 자동으로 계산됩니다.
   - 엑셀로 편집했다면 반드시 **"CSV UTF-8"** 형식으로 저장하세요.
2. 스크립트를 실행합니다.
   ```bash
   python 3_db_scripts/create_lotto_db.py
   ```
   - 실행하면 `assets/lotto.csv`와 `assets/db/lotto.db`가 함께 갱신됩니다.
3. 앱을 다시 빌드합니다.
   - 이미 설치된 앱은 업데이트 후 실행할 때 CSV의 새 회차를 DB에 자동으로 반영합니다.

## 빌드 방법

```bash
cd 1_app_flutter/lotto_app
flutter pub get
flutter build appbundle --release   # Play 스토어 업로드용 (.aab)
flutter build apk --release         # 폰에 직접 설치해 보는 용도 (.apk)
```

- iOS는 **Mac**에서만 빌드할 수 있습니다.
  ```bash
  cd ios && pod install
  ```
  이후 Xcode에서 Runner → Signing & Capabilities 의 Team을 선택하고, `flutter build ipa --release`를 실행합니다.
- `build/app/outputs/flutter-apk/app-release.apk`: 확인용으로 만든 APK가 들어 있습니다.
  - 디버그 키로 서명돼 있어 **스토어에 올릴 수는 없고**, 폰에 직접 설치해 테스트할 수만 있습니다.

## Android 릴리스 서명 (스토어 업로드 전 1회)

1. 업로드 키스토어를 만듭니다.
   - JDK의 `keytool`이 필요합니다. Android Studio에 포함된 JBR을 써도 됩니다.
   ```bash
   keytool -genkey -v -keystore C:/Users/review/upload-keystore.jks -keyalg RSA -keysize 2048 -validity 10000 -alias upload
   ```
2. `android/key.properties.example`을 복사해 `android/key.properties`를 만들고 비밀번호를 채웁니다.
3. 이제 `flutter build appbundle`을 실행하면 업로드 키로 서명됩니다.
   - `key.properties`가 없으면 지금처럼 디버그 키로 서명됩니다.
4. `.jks` 파일과 비밀번호는 안전한 곳에 백업하세요. 잃어버리면 앱을 업데이트할 수 없습니다.

## 적용한 개선 사항 (1~6)

### ① DB 용량 축소: 487MB → 48KB
- 앱이 쓰지 않던 `lotto_combinations`(814만 행)를 없앴습니다.
- `past_winners`만 담은 `assets/db/lotto.db`를 새로 만들었습니다.
- 이전 버전이 기기에 복사해 둔 `lotto_master.db`(487MB)는 앱이 실행될 때 자동으로 삭제됩니다.
- 결과: APK 48.6MB (Flutter 엔진 포함, 3가지 CPU용 합본). Play 스토어 AAB로 받으면 기기별로 약 15~20MB입니다.

### ② `is_past_winner` 오류 제거
- 원인은 `update_winners.py`의 예시 번호 2개가 그대로 실행된 것이었습니다.
- ①에서 해당 테이블과 컬럼이 사라져 문제 자체가 없어졌습니다.
- 원인 스크립트는 `4_backup/old_scripts/`로 옮겼습니다.

### ③ CSV 인코딩 통일
- `lotto.csv`를 CP949에서 UTF-8로 바꾸고, 쓸모없던 빈 열(`,,,,`)을 제거했습니다.
- 앱(`main.dart`)이 엑셀 "CSV UTF-8" 저장 시 붙는 BOM도 처리하도록 보완했습니다.
- 스크립트는 UTF-8과 CP949를 모두 읽을 수 있고, 저장은 항상 UTF-8로 합니다.

## 당첨번호 자동 갱신 (기획서 4단계)

```
동행복권·뉴욕주 공공데이터·FDJ → [GitHub Actions: 수집·검증] → docs/draws (GitHub Pages) → 앱이 새 회차만 받음
```

| 구성 | 파일 | 동작 |
|---|---|---|
| 수집 | `3_db_scripts/collect_draws.py` | 한국은 새 회차만, 해외는 전체를 받아 규칙 검사. 실패한 출처는 기존 데이터 유지 |
